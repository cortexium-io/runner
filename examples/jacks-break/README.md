# Connected Jack's Break delivery

`deliver` owns scoped Go development, correction, measurements, independent source
review, candidate publication, product qualification and the approved release.
The external chat submits the request and presents saved owner decisions. No model
or chat selects the next stage.

`admit → owner → check → measure → review → integrate → publish → qualify → prepare → [merge approval] → merge → backup → [production approval] → stop → migrate → pin → deploy → verify-live`

Checks, review and qualification each permit one in-scope correction. A selected
Go benchmark permits one further owner/measurement round. `benchmark: "none"`
records that measurement is outside this request. This is domain iteration;
execution retries neither judge the work nor replace correction policy.
The process permits at most 35 attempts, with bounded routes and no model fallback.
Implementation and review summaries are deliberately short; retained artifacts and
the private operator journal hold the full evidence. Native prompts state the
existing byte budget for the entire final JSON response, including its field
names and reason. Each field fitting separately does not satisfy that budget;
oversized responses remain execution failures.

The readiness step refreshes configured `refs/remotes/origin/main`, hydrates source
and pins the run's immutable base before model work. An explicit full commit is
also supported. It checks the selected build runtimes, a real scratch-image build,
protected closed-WAL backup permissions on Linux, npm TLS, target storage and an
isolated headless browser. The trusted Docker command includes its installed
runtime directory for credential-helper lookup in minimal SSH environments.
The readiness probe exercises the same builder as qualification. Its owned image
tag is removed with a bounded command, then absence is independently confirmed;
a lost cleanup acknowledgement cannot masquerade as a failed image build.
Coding and review have no release credentials. Publication consumes only the
retained, approved candidate. A correction advances the same owned draft PR using
an exact compare-and-swap; older candidate commits remain pinned.

One fixed project qualification operation packages the clean commit, checks its
manifest against Git, independently reproduces the Linux executable, builds the
artifact-only image, runs the frozen Nonogram development/held-out cohorts,
rehearses migration and previous-image recovery on copied data, probes every
advertised runtime choice and runs 36 headless desktop/mobile player journeys
across Chromium and WebKit. Every distinct advertised board geometry is also
opened at 320, 360 and 390 CSS pixels in both engines. Those paths come from the
same candidate's successful native publication/reopen proof.
Nonogram representatives include actual validated row-clue text width and column
clue count; Suguru includes its control maximum. Difficulty/density is grouped
only for fixed-track layouts. Missing footprint evidence cannot qualify an older
report. Receipts use compact metrics within the existing 128 KiB bound.
Image builds explicitly load their output and save a fresh `image.id`. Runtime
and executable checks use that immutable digest rather than the mutable tag;
missing or inconsistent export evidence stops qualification. Bounded private
build stdout/stderr are retained on success as well as failure. A successful
build exit alone never qualifies an image or permits a replacement build.
Browser acceptance checks actual board and internal overflow, initial New entry,
reachable primary controls, real touch edits, Undo/Redo and saved visible state
after reload and home Resume. Shikaku additionally proves the intended painted
cells without page pan, including one largest advertised board per engine and
viewport. A small overview needs working accessible `Zoom in` and `Fit board`
controls that make clues readable. Locator scrolling cannot rescue mobile entry
or edit failures. Chromium verifies Shikaku with native touch drag; WebKit verifies
its complete native two-corner/Add path because Playwright exposes no public
WebKit touch-drag API. Headless touch emulation does not prove physical-device
behavior. Unsupported new product obligations block rather than move to the chat.
Restricted macOS Chromium uses single-process mode and one context per browser
lifetime. Each device, geometry viewport and independent support profile gets
its own browser; a fresh context cannot reuse that single-process browser.

`frontend.json` selects the complete `deliver-frontend` variant. It uses the same
protected release suffix, with a frontend owner, scoped frontend command and
independent frontend review. Its `tests` input is a JSON array of 1..32 explicit
frontend-relative test files, for example
`["src/pages/shikaku/ShikakuWorkspace.test.ts"]`; glob patterns and command flags
are rejected. The command retains actual executed/failed/skipped assertion counts
and fails if any selected assertion is skipped or no tests run. It stages source
in owned scratch and links configured immutable dependencies; source and shared
caches stay read-only. The detailed artifact is retained rather than reused by
the text-only check cache. `package` remains the Go package for optional existing
measurement; use `benchmark: "none"` when irrelevant. The existing Go `deliver`
input contract is unchanged.

Scratch preparation includes explicitly imported repository JSON fixtures from
`docs/` and `testdata/`. It rejects escaped paths and symlinks, and copies no
unrelated fixture tree. A missing fixture blocks execution with its diagnostic.
The configured Node also runs the immutable `vue-tsc/bin/vue-tsc.js` with
`--noEmit --pretty false --project tsconfig.json`. TypeScript and scoped Vitest
share the existing check deadline. A conclusive type error still permits Vitest
collection so correction receives both complete diagnostics in the same artifact.
An authenticated compiler failure plus a matching source-transform failure may
request correction with `vitest_incomplete` and no invented assertion execution.
Unexpected, omitted or duplicate files, inconsistent counts and runtime gaps
still block; readiness still requires both checks to pass completely.
Missing tools/configuration or incomplete execution blocks acceptance. This adds
no Vite, SSR or prerender build to the scoped check.

An initial source check supplies real evidence before coding. Corrections and
review receive the complete bounded Vitest report, including canonical owned-file
identities and assertion diagnostics. Every selected file must execute assertions
exactly once; alias resolution cannot accept a different file with the same
basename. Missing, inconsistent or skipped-only evidence blocks execution rather
than inventing a source failure. Complete failed assertions request correction.
The raw report remains bounded to 8 MiB and the encoded proof to the existing
16 MiB artifact allowance.

`retained-frontend.json` selects `deliver-retained-frontend` for a preserved,
unreviewed mobile patch. A read-only measurement with `benchmark: "none"` restores
its seed before readiness. The initial frontend check then feeds the owner, and
later corrections receive the latest full report. Checks, independent review,
one publication and protected release follow under the existing limits.

Frontend and Nonogram research correction routes allow three returns to the owner
per source-feedback gate, still within 35 total attempts. An explicitly approved
`recover-corrections` action can grant that bounded policy to an exhausted older
run without changing its frozen definition or resetting its cumulative counters.
It resumes from the saved failed check result, preserves the same draft PR and
requires fresh downstream proof. It cannot bypass protected approvals, unknown
effects, source ownership checks or the total attempt ceiling.

`research-nonogram.json` is the evidence-only reproducibility process. It keeps
the original benchmark as a baseline and uses a separate diagnostic collector
for complete request, seed, phase and work records. Expected bounded rejection,
deadline and non-reproduction are observations; setup, invariant and collection
failures remain failures. Independent research review requires semantic evidence
completeness, not merely `evidence_status: provided`. Its completion returns the
reports and retained patch without integration, publication or release approval.
Original functional checks, release benchmarks and thresholds remain unchanged.

`retained-research-nonogram.json` selects `research-retained-nonogram`. Supply the
saved patch as `prior_patch` and retain its original base. The baseline and source
test receipt are collected against pristine source before the coding role reads
that reference and applies the in-scope work. This uses the normal edit contract,
not a source seed after baseline preparation. Candidate checks retain selected
test names, package identities and terminal outcomes in a bounded artifact for
both correction and independent review. Conclusive source failures request
correction; missing or incomplete execution evidence blocks acceptance.

`release-reviewed.json` is the complete model-free continuation for an already
accepted publication. Supply that publication's JSON receipt and its full base
commit as `source_ref`. Adoption verifies the original private journal and the
still-open GitHub PR/head/base. It creates no source edits, commits or duplicate
PR. Qualification runs again, followed by the same fresh merge, production and
recovery approval gates; prior approvals are not carried forward. The failed
development run remains intact. Its 16-attempt bound and per-visit limit of one
introduce no additional model allowance.

`investigate-retained.json` is the complete baseline-first entry for an
unreviewed retained scaffold. Supply its `patch` artifact and full base commit,
plus the same request/package/tests/benchmark inputs as `deliver`. A read-only
baseline command runs before infrastructure readiness and the first model turn;
its retained report is supplied directly to the investigator. A failed or missing
sample is marked failed and cannot qualify the candidate. Normal candidate
measurements remain strict. The existing correction/review/qualification/release
steps and their protected approvals follow, within the unchanged 35-attempt cap.
The original failed run and its patch stay preserved.

`investigate-source.json` uses the same complete investigation when the scaffold
is already committed. It measures the supplied source directly without inventing
a patch. `product.json` selects `deliver-product` for one combined frontend and
Go investigation candidate: baseline, readiness, one owner, frontend check, Go
check, measurement, independent combined review and the same protected suffix.
Its `frontend_tests` JSON file list is separate from the Go `tests` selector.
It retains the existing model, input/output and 35-attempt ceilings.

`retained-product.json` selects `deliver-retained-product` for an authorized
continuation of an unreviewed patch. Its five normal product inputs are joined by
`patch` and `original_baseline` artifact inputs. Candidate measurement restores
the patch before readiness, keeping the source's seed identity stable. Initial
frontend and Go checks collect conclusive source failures before another owner
turn; infrastructure failures still stop execution. The unchanged original
baseline is supplied separately to owner and reviewer. Current feedback falls
back to those initial command results, and the first post-owner measurement is
round 2. The owner receives the configured frontend file list as its eighth input.
Final checks, review, one publication and the unchanged protected release suffix
follow within the same 35-attempt/20-minute and model/storage limits. The original
failed run stays intact; a new continuation needs explicit authorization.

Investigation owners receive the complete baseline and current measurement
artifacts. Before the first candidate measurement, the declared one-level binding
`{"from_step":"measure","output":"artifact","previous":true,"fallback":{"from_step":"baseline","output":"artifact"}}`
selects the baseline. A fallback selects only an earlier configured step/output
of the same type; it cannot grant a literal artifact or nest another fallback.
Artifacts are copied into `.runner-tmp/inputs/<attempt>/<name>`, which is read-only
for coding and review. Other private state and the artifact store remain outside
worker access. Cleanup verifies ownership and retained bytes before removing only
that attempt's input directory; drift is preserved for inspection.

The measurement helper sets `RUNNER_MEASURE_EVIDENCE` to an owned scratch directory.
Native benchmarks may write complete synthetic request/seed/phase records as flat
regular JSON files there, at most 64 files and 8 MiB total. Links, directories,
invalid JSON and excess data are rejected. The files are embedded in the retained
`measurements.json`, within its 16 MiB artifact ceiling. Missing sidecars are
explicitly incomplete for collectors that promise structured evidence; the
unchanged original benchmark does not promise them. Provided files still require
semantic review. Verbose Go benchmark logs retain the original control records
within the existing output ceiling and never replace the candidate collector's
complete structured proof. No production/player logging is enabled by this
mechanism.

Browser layout verdicts require at least one loaded stylesheet and ready fonts.
A failed critical main-page resource gets one navigation retry with its failed
navigation diagnostics retained. Persistent resource failures remain operator
blockers; only a fully rendered overflow is a source correction. Puzzle creation
and hints are never replayed by this resource retry.

The legacy host browser's SSH forward requires its own positive loopback-bind signal before
journeys start. Startup is bounded, keeps private stderr diagnostics and may
reconnect once only after a confirmed pre-authentication banner timeout. It uses
a dedicated connection; a forwarding denial, an unrelated local listener or a
failure after binding cannot trigger browser replay. Process pipe copying also
preserves the configured stdout/stderr bounds.

## Installation

Copy `process.json` and `roles/` into the private project. Set executable and cache
paths in the command roles. Add this process to the project and select `deliver`
as its default. Keep local-only development processes available when explicitly
selected. Configure instance `release.github` with the trusted `gh` executable and
`release.command` with the fixed operator invocation, locally or through strict
SSH. Keep the operator policy, authentication and journals outside Git.

The operator's `delivery` settings select absolute runtime paths, read-only caches,
a public CA bundle and the existing generated-ownership command. Prefer the
[fixed Linux browser runtime](../../internal/release/browser-runtime/README.md)
through `delivery.browser_image` on the existing Docker engine when macOS
Seatbelt cannot provide WebKit's GUI-service registration. This adds no host
browser permissions. Legacy host runtimes instead configure `browser_executable`
(Chromium), `webkit_executable` and a matching Playwright `browser_module`.
Readiness launches both engines and requires a trusted native touch event and its
actual button action before model work. A missing engine is a precise prerequisite
failure, never a silent fallback. The macOS WebKit runtime can report zero touch
points despite correctly delivering native touch, so that property is not proof.
Use the exact Go 1.26.7, Node 24.21.0 and Python 3.12 build contract. For Homebrew
Node, export its normal public trust anchors with `tls.getCACertificates('default')`
under `--use-system-ca`; the sandbox receives this public PEM bundle through
`NODE_EXTRA_CA_CERTS`. It receives no normal account home or authentication.
Select the actual Git binary rather than Apple's `xcrun` wrapper, and give the
builder its owned temporary directory. Do not disable certificate verification.

Build `runner-release`, `runner-measure`, `runner-frontend-check`, `runner-snapshot` and
`runner-http-probe` from the reviewed Runner commit. The snapshot helper and HTTP
probe run on the Linux Docker host. Reuse the accepted project backup helper;
do not introduce Python source. The `delivery.probe` path names the installed Linux
HTTP probe. `delivery.ownership` is fixed argv for the owning Operations
`check-pr jacks-break` command, followed by Runner's exact PR number and
`--publish-status`.

Configure the frontend command's fixed helper, Node and immutable `node_modules`
paths, and include those runtime/dependency paths in the existing command read
allowlist. Install all browser prerequisites outside candidate roles. Existing
runtime reports without canonical publication paths cannot satisfy browser
contract 2; fresh qualification must produce the current report.

`delivery.storage_limit` is at most 8 GiB and `delivery.min_free` at least 5 GiB.
Admission and ongoing monitoring cover owned local and target storage. Admission
reserves 4 GiB of local build/correction space and 1 GiB on the target before any
model work. Settled
temporary source/caches and disposable data are cleaned; packages, journals and
recovery snapshots are retained. Storage exhaustion blocks new work instead of
raising allowances or deleting recovery evidence. These operator resources have
separate retention from the core run database.

Back up the pilot's database, owner token and configuration consistently before
cutover. Database format 2 stores settings and operational history as separately
bounded JSON documents in the same transaction. Existing format-1 history remains
readable and is not rewritten by opening it. Both documents obey `max_record`;
the existing database reservation and run count remain unchanged. An old binary
requires its matching pre-upgrade database backup after new format-2 runs exist.

## Recovery policy

- With `recover_before_migration: true`, a known final-backup failure can restart
  only the exact previous container after closed data, environment and no-mutation
  proof. Preparation failure before migration intent has the same boundary.
  Cancellation after an accepted stop, before migration, uses that compensation
  through the same durable operation, including a stop-result/cancel race.
  The release fails with the previous service's verified health recorded.
- A conclusively failed deployment before effects gets one configured retry.
  Failure after effects is inspected, then requires a saved owner decision for
  one reapplication of the same approved image and commit.
- A settled migration failure is inspected with Games stopped. A separate saved
  owner decision may restore the exact final snapshot and restart the previous
  image. The failed release remains failed, with its recovery recorded.
- Lost replies, interrupted effects and unsettled processes retain their original
  identity. They never authorize another release, migration or database restore.
  An SSH timeout before authentication gets one bounded reconnect; a disconnect
  after remote dispatch never gets that retry. The same boundary covers Docker's
  wrapped SSH error during pre-solve worker discovery and read-only queries;
  mutating Docker operations never receive that general query retry.
- Before release approvals or a new production stop, the core checks remaining
  attempts against the closed release suffix, including unused deployment retry
  and inspection/reapplication routes. Thin budgets wait before effects and retain
  qualification evidence. No allowance is increased automatically; already started
  operations retain their normal reconciliation path.

Merge approval does not approve production. Production approval does not approve
database restoration. Shared Docker cleanup and unrelated changes are outside
these recovery routes. The qualified database contract supports migration 0017
and later releases with no schema changes; other migrations need an explicitly
qualified project contract.

An authorized verifier-policy upgrade may configure one `publication_transition`
with `previous_policy_sha256`, `pr`, `head` and `base`. This permits only model-free
adoption of that exact authenticated publication into the new policy. Live PR
identity checks, fresh qualification and all protected approvals still apply.
It does not accept previous-policy qualification or release effects.

## Verification

Ordinary tests are model-free. Configuration tests prevent skipped approvals and
forged receipts. The core integration fixture covers correction, benchmarks,
reconnect, both release decisions, bounded recovery and the combined 35-attempt
path within the pilot's record allowance. SQLite tests preserve legacy history
through upgrade and reject oversized settings or history.

The opt-in `TestDeliveryPlatformQualification` uses a private
`RUNNER_DELIVERY_PLATFORM_POLICY` and `RUNNER_DELIVERY_PLATFORM_BINARY` to test
actual installed tools without models or production mutations. Its synthetic
publication journal is restricted to separate `-qualification/` storage.
`TestDeliveryPlatformImageExport` additionally takes
`RUNNER_IMAGE_EXPORT_CONTEXT`, an already reproduced retained context. It tests
the actual export and image/executable checks after removing its disposable tag.
It preserves existing images, product runs, approvals and production.
`TestDeliveryPlatformRecovery` additionally requires the disposable Linux helper
from `testdata/release-lab`, selected by `RUNNER_DELIVERY_FAULT_HELPER`. It creates
a separate Compose project and synthetic database. Run these platform exercises
serially; no failure is injected into production. Test approval grants no
production authority. Real delivery stops at the actual saved owner decisions.
`TestDeliveryPlatformBrowserReadiness` accepts the synthetic
`testdata/browser-acceptance/main.mjs` fixture. It proves both engines pass native
touch/Undo/Redo/reload at all three widths, and rejects clipped boards, wrong entry
scroll, offscreen controls and ignored touch without opening a product service.
The fixed-image equivalent is `TestDeliveryPlatformBrowserContainerReadiness`;
it retains the enforced Docker inspection and exact image/driver/version proof.
`TestDeliveryPlatformBrowserContainerCancellation` separately proves cancellation
after positively observed dispatch, uncertainty preservation and exact cleanup.
